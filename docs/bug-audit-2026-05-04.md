# Bug audit — 2026-05-04

Investigation of three live HTTP 500s reported on the school-admin Filament panel
served at `https://sms.kynexsolutions.com/admin` (and equivalently `https://aqmdigital.com/admin`).
All three errors reproduced live in the user's browser between **18:18–18:29 UTC** today (23:18–23:29 PKT).

> **Naming clarification:** `/admin` is the **school-admin** Filament panel (path `admin`,
> panel id `school-admin`). The SaaS super-admin panel lives at `/saas` (panel id `saas-admin`).
> The user reported these as "/admin under super-admin login" — they were authenticated to
> the school panel via the central-host session-tenancy fallback, not the SaaS panel.

---

## Critical bugs (block all SaaS admin work)

### Bug A — `/admin` returns 500: `Route [filament.school-admin.auth.login] not defined`

- **URL:** `/admin` (school-admin panel root / dashboard)
- **Log entry:** `laravel.log:102`, timestamp `2026-05-04 18:18:21`
- **Exception:** `Symfony\Component\Routing\Exception\RouteNotFoundException`
- **Top frames:**
  1. `Illuminate\Routing\UrlGenerator->route('filament.school-admin.auth.login', …)` — `helpers.php:870`
  2. `Filament\Panel->route('auth.login', …)` — `HasRoutes.php:106`
  3. `Filament\Panel->getLoginUrl(…)` — `HasAuth.php:386`
  4. `Filament\Http\Middleware\AuthenticateSession->redirectTo(…)` — `Filament/AuthenticateSession.php:12`
  5. `Illuminate\Session\Middleware\AuthenticateSession->logout(…)` — Laravel `AuthenticateSession.php:67`
- **Trigger flow:** Laravel's `AuthenticateSession` middleware decided the session must be
  invalidated mid-request (mismatch between session `password_hash_*` and the user's current
  hash, or `session.user_id` differing from the resolved auth user). Filament's wrapper
  around this middleware then calls `Filament::getLoginUrl()`, which resolves to
  `route('filament.school-admin.auth.login')`. That route does not exist.
- **Why it does not exist:** `app/Providers/Filament/SchoolAdminPanelProvider.php:140-150`
  intentionally does **not** call `->login()` on the panel because `/admin/login` is shadowed
  by `routes/web.php:64` (a redirect to the school portal `/login`). The provider only
  rebinds `LogoutResponseContract` to `SchoolAdminLogoutResponse` (which returns
  `route('school.login')`), but it does **not** override `Filament\Panel::getLoginUrl()` —
  so any path inside Filament that calls `getLoginUrl()` (such as session
  invalidation) crashes.
- **Root cause:** missing override of the school-admin panel's login URL resolution.
  The existing `SchoolAdminLogoutResponse` covers the explicit logout flow but not
  the implicit session-invalidation flow.
- **Suggested fix scope:** in `SchoolAdminPanelProvider`, either
  (a) call `->loginRouteAction()` / `->login(\Filament\Pages\Auth\Login::class)` and then
  let the panel emit the route as a redirect to `/login` via web.php, or
  (b) catch this at middleware-level by registering a panel boot callback that overrides
  `Panel::getLoginUrl()` to return `route('school.login')`. Option (b) leaves the existing
  intentional shadowing of `/admin/login` untouched.
- **Severity:** **critical** — the panel root is unusable whenever a session-mismatch
  fires. Until fixed, every super-admin / school-admin user is one session-invalidation
  away from a hard 500.

## Major bugs (specific feature broken)

### Bug B — `/admin/financial-report` returns 500: `Route [financial-report.print] not defined`

- **URL:** `/admin/financial-report`
- **Log entry:** `laravel.log:162` and `laravel.log:334`, timestamps `2026-05-04 18:25:54` and `18:26:42`
- **Exception:** `Illuminate\View\ViewException` wrapping `RouteNotFoundException`
- **View:** `resources/views/filament/school-admin/pages/financial-report.blade.php:73`
  ```blade
  href="{{ route('financial-report.print', ['from' => $from, 'to' => $to]) }}"
  ```
- **Top frames:**
  1. `Illuminate\View\Engines\CompilerEngine->handleViewException(...)` — `ExtendedCompilerEngine.php:58`
  2. Through `Livewire\Mechanisms\ExtendBlade\ExtendedCompilerEngine->evaluatePath(...)`
  3. `Illuminate\View\View->render(...)`
  4. `Livewire\Mechanisms\HandleComponents\HandleComponents->trackInRenderStack(App\Filament\SchoolAdmin\Pages\FinancialReport, ...)`
  5. `Livewire\LivewireManager->mount('App\\Filament\\SchoolAdmin\\Pages\\FinancialReport', ...)`
- **Root cause:** the controller class `app/Http/Controllers/FinancialReportPrintController.php`
  was added in commit **b3f99fd** ("chore: recover container drift before image rebuild") but
  no `Route::get(...)->name('financial-report.print')` was registered in `routes/web.php` or
  `routes/tenancy.php`. The blade view was added in the same commit and references the
  unbound name.
- **Suggested fix scope:** register a route in `routes/web.php` (single line) under the
  appropriate tenancy middleware, e.g.
  ```php
  Route::middleware([InitializeTenancyBySubdomainOrDomain::class, 'auth:school_users'])
      ->get('/financial-report/print',
            [FinancialReportPrintController::class, '__invoke'])
      ->name('financial-report.print');
  ```
  (verify the controller's actual action method name when wiring this).
- **Severity:** **major** — the entire FinancialReport page 500s on render because the blade
  link is rendered eagerly inside the page body, not inside a click handler.

## Common root causes

The three bugs do **not** share a single underlying defect, but they share a single
**origin**: commit **b3f99fd** ("chore: recover container drift before image rebuild",
2026-05-03). That commit imported 95 files of pre-existing drift into git, including:

- `FinancialReport` page + blade view — blade references `route('financial-report.print')` (Bug B)
- `FinancialReportPrintController` — added but no route registration anywhere (Bug B)
- The four analytics widgets named in Bug C (column-name drift)
- `FeeReceiptController`, `CertificateVerificationController`, `StudentVerificationController`
  — also imported as orphan controllers with no route registration. **No template currently
  references them**, so they are latent (no live error today), but they are bugs-in-waiting
  the moment any UI links to them.

Bug A predates the drift recovery: `SchoolAdminPanelProvider` at line 140-150 has had this
gap since the panel was first created. The drift recovery did not introduce or fix it.

The drift-recovery doc (`docs/drift-recovery-2026-05-02.md`) noted that all *migrations*
were applied to live tenant DBs; it did not catch (1) blade views referencing unbound
route names, (2) orphan controllers, or (3) widgets using fictitious column names. A
post-recovery sweep for these classes of issue is warranted.

## Suggested fix order

1. **Bug A first** (1 panel-provider override) — this unblocks `/admin` regardless of any
   other bug, and unblocks future debugging because right now a single auth-mismatch turns
   every panel page into a 500. Smallest blast radius (one file), highest impact.
2. **Bug B** (1 line in `routes/web.php`) — quick win, restores the FinancialReport page.
   Verify the controller's actual action signature when wiring.
3. **Bug C** (4 column-name fixes across 4 widget files) — the longest tail by file count
   but each edit is mechanical (column rename). Group as one PR; after `amount_paisas` is
   corrected in `FeeCollectionTrendWidget`, also fix the latent `paid_at` reference at
   line 39 of the same file in the same edit.
4. **Latent orphan controllers** (out-of-scope sweep) — register routes for
   `FeeReceiptController`, `CertificateVerificationController`,
   `StudentVerificationController` **only when** a UI surface needs them. Until then,
   leaving them unbound is correct.
