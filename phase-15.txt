## PART 1: WINDOW FUNCTIONS — REPLACE PHP LOOPS WITH SQL

### 1a. ExamService::assignRanks() → PostgreSQL RANK()

Current implementation (app/Services/ExamService.php:162-193) loads
all passing ExamResult rows into PHP, loops to assign ranks with a
manual tie-skip counter, and issues one UPDATE per student. For a
class of 500 students, that's 500 individual UPDATE queries.

Replace with a single raw query:

```php
public function assignRanks(string $examId, string $classId): void
{
    // Use PostgreSQL RANK() window function — single query replaces N+1 loop.
    // RANK() handles ties automatically: tied students get the same rank,
    // and the next rank skips (e.g., 1, 2, 2, 4 — identical to old PHP logic).
    DB::statement("
        UPDATE exam_results er
        SET rank = ranked.r
        FROM (
            SELECT id,
                   RANK() OVER (ORDER BY marks_obtained DESC) AS r
            FROM exam_results
            WHERE exam_id = ?
              AND class_id = ?
              AND status = ?
        ) ranked
        WHERE er.id = ranked.id
    ", [$examId, $classId, ExamResultStatus::Pass->value]);

    // Null out ranks for non-passing students
    ExamResult::where('exam_id', $examId)
        ->where('class_id', $classId)
        ->where('status', '!=', ExamResultStatus::Pass)
        ->update(['rank' => null]);
}
```

Remove the old `$rank`, `$prevMarks`, `$skip` loop entirely.

### 1c. AttendanceService — monthly summary via SQL

Add a new method that computes monthly attendance for all students
in a class using SQL aggregation instead of per-student PHP loops:

```php
/**
 * Get monthly attendance percentages for all students in a class.
 * Returns one row per student with aggregated counts.
 */
public function getClassMonthlyAttendance(
    string $classId,
    string $sectionId,
    int $year,
    int $month,
): Collection {
    return DB::table('attendance_records')
        ->select([
            'student_id',
            DB::raw("COUNT(*) as total_days"),
            DB::raw("COUNT(*) FILTER (WHERE status = 'present') as present"),
            DB::raw("COUNT(*) FILTER (WHERE status = 'absent') as absent"),
            DB::raw("COUNT(*) FILTER (WHERE status = 'late') as late"),
            DB::raw("COUNT(*) FILTER (WHERE status = 'half_day') as half_day"),
            DB::raw("COUNT(*) FILTER (WHERE status = 'excused') as excused"),
            DB::raw("ROUND(
                (COUNT(*) FILTER (WHERE status = 'present')
                 + COUNT(*) FILTER (WHERE status = 'late')
                 + COUNT(*) FILTER (WHERE status = 'half_day') * 0.5
                ) * 100.0 / NULLIF(COUNT(*), 0), 2
            ) as attendance_percentage"),
        ])
        ->where('class_id', $classId)
        ->where('section_id', $sectionId)
        ->whereYear('date', $year)
        ->whereMonth('date', $month)
        ->groupBy('student_id')
        ->get();
}
```

### 1d. FeesService — collection summary via SQL

Add a new method to FeesService that computes per-class fee
collection using SQL aggregation:

```php
/**
 * Get fee collection summary for a class using SQL aggregation.
 * Replaces PHP-side sum/count over loaded collections.
 */
public function getClassFeeCollectionSummarySQL(
    string $classId,
    ?string $sectionId,
    string $academicYearId,
): array {
    $query = DB::table('student_fees')
        ->join('students', 'student_fees.student_id', '=', 'students.id')
        ->where('students.class_id', $classId)
        ->where('student_fees.academic_year_id', $academicYearId);

    if ($sectionId) {
        $query->where('students.section_id', $sectionId);
    }

    $result = $query->selectRaw("
        COUNT(DISTINCT student_fees.student_id) as total_students,
        COALESCE(SUM(student_fees.amount_paisas + student_fees.fine_paisas - student_fees.discount_paisas), 0) as total_fees,
        COALESCE(SUM(student_fees.paid_paisas), 0) as total_collected
    ")->first();

    $totalFees = (int) $result->total_fees;
    $totalCollected = (int) $result->total_collected;

    return [
        'total_students'  => (int) $result->total_students,
        'total_fees'      => $totalFees,
        'total_collected'  => $totalCollected,
        'total_pending'    => $totalFees - $totalCollected,
        'collection_rate'  => $totalFees > 0
            ? round(($totalCollected / $totalFees) * 100, 2)
            : 0,
    ];
}
```

```php
                2
            ) AS attendance_percentage

        GROUP BY student_id, class_id, section_id,

        ON mv_student_attendance_summary (student_id, year, month)
    ");

    // Monthly revenue totals per tenant. Dashboards and reports
    // read from here instead of aggregating student_fees + fee_payments.
    DB::statement("
        CREATE MATERIALIZED VIEW IF NOT EXISTS mv_fee_collection_summary AS
        SELECT
            s.class_id,
            s.section_id,
            sf.academic_year_id,
            EXTRACT(YEAR FROM sf.created_at)::int AS year,
            EXTRACT(MONTH FROM sf.created_at)::int AS month,
            COUNT(DISTINCT sf.student_id) AS total_students,
            COALESCE(SUM(sf.amount_paisas + sf.fine_paisas - sf.discount_paisas), 0) AS total_fees_paisas,
            COALESCE(SUM(sf.paid_paisas), 0) AS total_collected_paisas,
            COALESCE(SUM(sf.amount_paisas + sf.fine_paisas - sf.discount_paisas - sf.paid_paisas), 0) AS total_pending_paisas,
            CASE
                WHEN SUM(sf.amount_paisas + sf.fine_paisas - sf.discount_paisas) > 0
                THEN ROUND(
                    SUM(sf.paid_paisas) * 100.0
                    / SUM(sf.amount_paisas + sf.fine_paisas - sf.discount_paisas), 2
                )
                ELSE 0
            END AS collection_rate
        FROM student_fees sf
        JOIN students s ON sf.student_id = s.id
        GROUP BY s.class_id, s.section_id, sf.academic_year_id,
                 EXTRACT(YEAR FROM sf.created_at), EXTRACT(MONTH FROM sf.created_at)
    ");

    DB::statement("
        CREATE UNIQUE INDEX idx_mv_fee_collection_class_month
        ON mv_fee_collection_summary (class_id, section_id, academic_year_id, year, month)
    ");
}
```

## PART 4: PARTIAL INDEXES — SPEED UP FILTERED QUERIES

### 4a. Migration: add partial indexes

Create migration: add_partial_indexes_to_hot_tables
File: database/migrations/tenant/2026_04_05_102_add_partial_indexes.php

Partial indexes only index rows matching the WHERE condition,
keeping the index small and fast for the most common queries.

```php
public function up(): void
{
    // ── Active students — most queries filter by status='active' ──
    // The students table may have thousands of inactive/graduated rows.
    // Dashboards, attendance pages, and fee pages always query active only.
    DB::statement("
        CREATE INDEX IF NOT EXISTS idx_students_active
        ON students (class_id, section_id)
        WHERE status = 'active'
    ");

    // ── Pending approvals — the approval queue only shows pending ──
    // Most approval_requests are resolved (approved/rejected).
    // The pending queue page scans only this small subset.
    DB::statement("
        CREATE INDEX IF NOT EXISTS idx_approvals_pending
        ON approval_requests (created_at DESC)
        WHERE status = 'pending'
    ");

    // ── Unpaid fees — fee collection pages filter unpaid ──────────
    // Most fee records are eventually paid. The "collect fee" page
    // and overdue reports only care about unpaid/partial rows.
    DB::statement("
        CREATE INDEX IF NOT EXISTS idx_fees_unpaid
        ON student_fees (student_id, due_date)
        WHERE status != 'paid'
    ");

    // ── Active device tokens — FCM driver always queries active ──
    // Deactivated tokens (InvalidRegistration) accumulate over time.
    DB::statement("
        CREATE INDEX IF NOT EXISTS idx_device_tokens_active
        ON device_tokens (school_user_id)
        WHERE is_active = true
    ");
}

{
```

```php
{
    // Add the tsvector column for full-text search
    DB::statement("
        ALTER TABLE students
        ADD COLUMN IF NOT EXISTS search_vector tsvector
    ");

    // GIN index for fast full-text lookups
    DB::statement("
        CREATE INDEX IF NOT EXISTS idx_students_fts
        ON students USING GIN(search_vector)
    ");

    // of name or admission_number fields.
    DB::statement("
        CREATE OR REPLACE FUNCTION students_search_vector_update() RETURNS trigger AS $$
        BEGIN
            NEW.search_vector :=
                setweight(to_tsvector('simple', COALESCE(NEW.first_name, '')), 'A') ||
                setweight(to_tsvector('simple', COALESCE(NEW.last_name, '')), 'A') ||
                setweight(to_tsvector('simple', COALESCE(NEW.admission_number, '')), 'B') ||

            setweight(to_tsvector('simple', COALESCE(last_name, '')), 'A') ||
            setweight(to_tsvector('simple', COALESCE(admission_number, '')), 'B') ||
```

### 5b. Search scope on Student model

Add to app/Models/Tenant/Student.php:

```php
/**
 * Full-text search scope using PostgreSQL tsvector.
 * Supports partial matching via :* prefix operator.
 *
 * Usage: Student::search('ahmed kh')->get()
 */
public function scopeSearch(Builder $query, string $term): Builder
{
    $sanitized = preg_replace('/[^\w\s]/', '', $term);
    $tsQuery = collect(explode(' ', trim($sanitized)))
        ->filter()
        ->map(fn ($word) => $word . ':*')
        ->implode(' & ');

    return $query->whereRaw('search_vector @@ to_tsquery(\'simple\', ?)', [$tsQuery])
        ->orderByRaw('ts_rank(search_vector, to_tsquery(\'simple\', ?)) DESC', [$tsQuery]);
}
```

## PART 8 (MEDIUM PRIORITY): PGBOUNCER CONFIGURATION

### 8a. PgBouncer setup notes (infrastructure, not code)

Configure PgBouncer in transaction pooling mode before production
launch. At 20+ concurrent tenants with heavy queries, direct
PostgreSQL connections will exhaust max_connections (default 100).

Recommended pgbouncer.ini settings:
```ini
[databases]
; Central database
kynexedu_central = host=127.0.0.1 port=5432 dbname=kynexedu_central

; Wildcard for tenant databases (stancl/tenancy creates these dynamically)
* = host=127.0.0.1 port=5432

[pgbouncer]
listen_addr = 127.0.0.1
listen_port = 6432
pool_mode = transaction
max_client_conn = 500
default_pool_size = 25
min_pool_size = 5
reserve_pool_size = 5
server_lifetime = 3600
server_idle_timeout = 600
```

Update .env for production:
```
DB_PORT=6432          # PgBouncer port instead of 5432
DB_HOST=127.0.0.1    # PgBouncer address
```

IMPORTANT: With transaction pooling, SET commands (like app.user_role
for RLS) only persist within a single transaction. The
SetPostgresUserRole middleware must ensure the SET and subsequent
queries run within the same database transaction. Verify this works
correctly with PgBouncer before deploying RLS policies.

### 8b. Laravel config adjustment

In config/database.php, add a note:

```php
// When using PgBouncer in transaction pooling mode:
// 1. Persistent connections must be disabled (no 'persistent' => true)
// 2. Session-level SET commands (e.g., SET app.user_role) only persist

```

## PART 9 (LOW PRIORITY — DOCUMENT ONLY, DO NOT IMPLEMENT)

Add this block as a comment at the top of a new file:
docs/phase-15-deferred-decisions.md

### 9a. PostgreSQL schemas per tenant — NOT NEEDED

The stancl/tenancy database-per-tenant model already provides
stronger isolation than schemas. A dedicated database per tenant
means: separate pg_dump, independent PITR, no cross-tenant query
risk. Schema-per-tenant is a downgrade. Skip this.

### 9b. pg_cron — NOT NEEDED

pg_cron only makes sense if you move scheduled tasks out of
Laravel's scheduler into PostgreSQL. Laravel's scheduler
(routes/console.php) already handles the materialized view
refresh and all other periodic tasks. Adding pg_cron creates
two scheduling systems to maintain. Skip this.

### 9c. ULID-as-varchar — NOT A PROBLEM

PostgreSQL optimizes varchar(26) comparisons well. ULID's
time-ordered property means B-tree indexes stay mostly sequential.
Changing to a binary type (bytea or custom type) would require
rewriting every migration, every foreign key, and every model cast.
The performance gain is negligible. Leave as-is.
