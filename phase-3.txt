### 2a. Approval Request Service
Create app/Services/ApprovalService.php

Methods:
  request(
    string $actionType,
    Model $subject,
    Model $requestedBy,
    array $payload = [],
    ?string $tenantId = null,
    ?Carbon $expiresAt = null
  ): ApprovalRequest

  approve(ApprovalRequest $req, Model $reviewer, 
          string $notes = ''): void
  — Sets status=approved, reviewed_by, reviewed_at.
  — Fires ApprovalGranted event.
  — Dispatches ExecuteApprovedAction job.

  reject(ApprovalRequest $req, Model $reviewer,
         string $notes = ''): void
  — Sets status=rejected, fires ApprovalRejected event.

  cancel(ApprovalRequest $req): void

### 2b. ExecuteApprovedAction Job
app/Jobs/ExecuteApprovedAction.php

Handles executing the actual action after approval.
Uses a match() on $approval->action_type:

  'delete_student' => Student::find($id)->delete()
  'expel_student' => Student::find($id)
                       ->update(['status'=>'expelled'])
  'bulk_fee_waiver' => (applies waiver from payload)
  'large_expense' => Expense::find($id)
                       ->update(['approval_status'=>'approved'])
  'change_fee_structure' => (applies fee change from payload)
  'suspend_staff' => SchoolUser::find($id)
                       ->update(['is_active'=>false])
  'role_assignment' => (assigns role from payload)
  'role_revocation' => (revokes role from payload)
  default => Log::warning('Unknown action type: '.$type)

### 2c. Actions requiring approval (middleware approach)
Create app/Filament/Concerns/RequiresApproval.php trait.

Actions in these resources must call ApprovalService::request()
instead of executing directly, when the current user does NOT 
have 'bypass_approvals' permission:

  StudentResource:
    - Delete student → requires approval (action_type: delete_student)
    - Expel student → requires approval (expel_student)
    - Bulk status change → requires approval (bulk_status_change)

  FeeResource (Phase 4 — stub the check now):
    - Waive fee > PKR 5,000 → requires approval (fee_waiver)
    - Change fee structure → requires approval (change_fee_structure)

  ExpenseResource:
    - Any expense > PKR 50,000 → requires approval (large_expense)

  SchoolUserResource:
    - Assign sensitive role (ACCOUNTANT, CAMPUS_OWNER) 
      → requires approval (role_assignment)
    - Disable staff account → requires approval (suspend_staff)

### 4c. ProcessNotificationQueue Job
app/Jobs/ProcessNotificationQueue.php

Processes pending notifications_queue records:
  - For SMS: uses SmsServiceFactory::make($tenant)->send()
  - For WhatsApp: uses WhatsAppServiceFactory::make($tenant)->send()
  - For Email: uses Resend via Laravel Mail
  - For in_app: creates in_app_notifications record
  - Logs result to communication_logs table
  - Updates notification_queue status
  - On failure: increments attempts, retries up to 3 times
  - After 3 failures: status = failed, logs error
